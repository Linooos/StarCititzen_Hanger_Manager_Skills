# 星际公民 CCU 升级链规则

> 原文规则，作为后续功能开发的依据。可随时修改完善。

## 1. 基本概念

### 1.1 升级包 (Upgrades / CCU)

- 升级包是在机库中船只项目（Standalone Ships）上应用的，用于升级到价格更贵的船只。
- 升级包可以不断叠加，以追求更高价值的船只。
- 升级包具有 `from`（原始船只）和 `to`（升级后船只）属性。
- 升级包并非以实际价值计算，部署时只能应用到机库内已有的对应原始船只（from 船），不能应用到同价值的其他船只。

### 1.2 Warbond CCU

- Warbond CCU 代表官方打折获取的升级包。
- **实际价值**：玩家实际消费的金额（现实货币）。
- **价值**：原船只升级到目标船只价格间的差额。
- 两者可能不对等（打折导致实际价值低于标称价值）。

### 1.3 种子船 (Seed Ship)

- 船只（Standalone Ships）拥有附加属性：当前具体船只、保险信息、附赠物品、游戏资格等。
- 种子船是整个升级链条的基础、起点。
- 永久保险（LTI）的种子船价值最高。

### 1.4 溶解 (Exchange / Melt)

- 机库内项目可以被溶解（exchange），返还玩家花费的实际价值等额的信用点数（Store Credit）。
- 信用点数可作为代金券在商店（Pledge Store）消费，但无法购买打折商品（通常带 Warbond 词条）。
- 被溶解的项目从机库中消失。

### 1.5 信用点 (Store Credit)

信用点是 RSI 商店的虚拟代金券，可用于购买非 Warbond 商品。

**获取来源：**

1. **溶解自有项目** — 将自己购买的机库项目溶解（Exchange），返还实际消费金额等额的信用点。
2. **溶解他人赠送项目** — 从其他玩家处获赠的机库项目，溶解后同样获得信用点。但此类信用点的**实际价值（现实货币）不等同于其面值**，因为赠送项目通常以非官方渠道交易获得，存在折扣。

**信用点实际价值计算（赠送项目）：**

```
赠送项目溶解所得信用点的实际价值 = 面值 × 折扣率
```

- 非官方交易通常为 **5~7 折**（50%~70% off），默认以 **6.5 折（65%）** 计算。
- 例：某船商店标价 $100，玩家以 $65（6.5 折）从他人处购得，溶解后面值 $100 信用点，但实际成本仅 $65。

**信用点使用限制：**

- 信用点**无法购买 Warbond 项目**（Warbond 需全新现金）。
- 因此 Warbond CCU 的省钱效果来自"现金部分"，应尽可能让 Warbond CCU 的起始船只价值**接近目标船只的 Warbond 价值**，以最大化节省真实货币。

**Warbond CCU 起始船选择规则：**

船只价值的最小跳动单位为 **$5**，两船间至少相隔 $5。根据"同价船不可互转"原则：

```
Warbond 目标价值 = 目标船常规价值 - Warbond 优惠金额
理想起始船价值 ≈ Warbond 目标价值 - $5
```

例：目标船 Mercury 常规 $260，Warbond 优惠 -$20 → Warbond 价值 $240。则此 Warbond CCU 的理想起始船应尽量接近 $240 - $5 = **$235**，而非使用更低价（如 $200）的船只作为起点——因为 $200→$240 的差价中，$40 可用信用点填补，只有 Warbond 节省的 $20 是现金收益。

### 1.6 升级包部署

- 升级包只能对对应的原始船只（from 船）进行升级。
- 升级包附带的其他属性或物品并入原始船只的附带物品（如皮肤、保险等）。
- 升级包的部署不可逆（除非溶解整个升级后的船只包）。

## 2. 保险规则

- 船只保险不能通过升级包携带的保险进行不断叠加。
- 保险取最高值：如船只中同时携带 120 月保险和永久保险（LTI），则取永久保险（LTI）为最终保险。
- 保险等级从低到高（大致）：3mo < 6mo < 12mo < 24mo < 120mo < LTI（永久）

## 3. 升级后船只属性

- 如船只（Standalone Ships）具有 `upgrades` 缩进栏（`js-upgrade-log upgrade`），意味着该船只已经应用过其他升级包。
- 应用升级包后，原始标签显示的是原船名，实际代表的是升级后的新船只。
- 叠加升级包后，最终船只价值为**最后部署的升级包的"升级后船只"的价值**。

## 4. 价值计算

### 4.1 实际价值计算

```
船只实际价值 = 种子船(Standalone Ship)实际价值 + 升级包1实际价值 + 升级包2实际价值 + ...
```

### 4.2 最终船只价值

```
最终船只价值 = 最后一个升级包的目标船(升级后船只)的价值（商店标价）
```

### 4.3 升级效率

```
升值率 = 最终船只价值 / 实际总价值
节省金额 = 最终船只价值 - 实际总价值
```

## 5. CCU 链条优化目标

用更少的实际价值（玩家的现实货币）获取价值更高的船只。

即：在所有可能的升级包组合中，找出实际总价值最低但最终船只价值最高的路径。

## 6. 爬取数据要求

为支持 CCU 计算，需从机库页面爬取以下额外信息：

### 6.1 Standalone Ships 附加信息
- 附带物品列表（皮肤、装备、 flair 等）
- 保险信息（类型、时长）
- 当前实际船只名称（展开 details 后的实际船名，非标签显示名）
- 游戏资格（星战公民下载权限、42中队权限等）
- 已应用的升级包列表（`js-upgrade-log` 缩进内容）

### 6.2 Upgrades 附加信息
- 原始船只（from ship）：名称 + 商店价值
- 升级后船只（to ship）：名称 + 商店价值
- Warbond 状态：实际价值 vs 标称差额
- 是否可溶解（not buybackable）

### 6.3 通用信息
- 机库项目的实际溶解价值（exchange value / melt value）
- 项目赠送/活动来源标记

### 6.4 升级链提取实现注意事项

**DOM 结构特点：**
- 页面中所有 `.js-upgrade-log` 按钮**共享同一个** `.pledge-upgrade-log-rows` 容器
- 每次点击按钮会通过 AJAX 加载对应的升级链内容，**覆盖**之前的内容
- 因此必须采用 **点击 → 等待加载 → 提取 → 点击下一个** 的顺序流程，不可批量并发

**提取流程（`expandUpgradeLogs` 函数）：**
1. 遍历所有 `.js-upgrade-log` 按钮
2. 对每个按钮：`force click`（因 AJAX 加载导致元素位置不稳定）
3. 等待 2 秒让 AJAX 完成
4. 从 `.pledge-upgrade-log-rows .row` 提取链数据
5. 保存为 `upgradeChains[i]`，继续下一个按钮

**链行解析：**
- 每行格式：`"{date} Upgrade applied: #{ccuId} Upgrade - {from} to {to} {Warbond/Standard} Edition, new value: ${value} USD"`
- DOM 中行顺序为**最新在前**（倒序），需要 `.reverse()` 反转为应用顺序（从旧到新）

**链与物品关联：**
- `expandUpgradeLogs` 按按钮点击顺序返回 `chains[]` 数组
- `scrapeCategory` 中遍历 `pageItems`，按 `upgraded === true` 的顺序依次匹配 `chains[chainIdx++]`

**`upgradeChain` 步骤数据结构：**
```js
{ date, ccuId, from, to, isWarbond, newValue }
```
